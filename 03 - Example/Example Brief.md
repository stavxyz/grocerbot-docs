# Example

Everything in this folder is example material from DRAPER, the app this method was built on, kept so you can see what a real run of the visual documentation process produces and reads from. None of it describes your system, none of it is a template to copy forward, and no run on your app should treat it as a source. It pairs with the example pages kept in the duplicated Figma file: the example System Legend, the example System Registry, and the example output phases there were produced by this process running against this material.

## What is in here

- **Logic - Harness (DRAPER).md**: the filled-in version of the root `Logic - Harness.md` template. This is the standard every DRAPER run reconciled sources against: what the system is now, what sits outside it, what it replaced, and where the correction came from.
- **Before-After - How Draper Runs.html**: the DRAPER architecture in full, both sides, old and new. The fuller reference behind the harness document.
- **Function - Visual Documentation (DRAPER).md**: the DRAPER version of the root Function, with real phase names, a real naming conflict being managed, and a real target board. Shows what the root template grows into once a system's specifics accumulate in it.
- **Sources Brief (DRAPER).md**: the map of DRAPER's full sources folder, thirteen subfolders of transcripts, briefs, code snapshots, prompt exports, and past attempts. Shows what a mature `01 - Sources` looks like and how read order and source standing get recorded.
- **System Lexicon (DRAPER).md**: DRAPER's glossary, newest on top, with term strength tracked per entry and superseded sections preserved at the strength they had. This is the shape to copy when your own lexicon starts: not the terms, the discipline of dating entries, recording how settled each term is, and never silently rewriting history.
- **Reviews/26.09.03**: a real review pass on the finished visual documentation, packaged as voice reviews, verbatim transcripts, a video walkthrough, and a small static review site. The transcripts are the valuable part: the team talking through the visual documentation itself, what worked on the boards, and what got corrected. Its README describes the packaging and deploy; that part is specific to how DRAPER shipped it.
