# Protocol

The hard rules for every substantive task that creates, revises, interprets, or evaluates the documentation in this repo: reading, the Context Record, and reporting.

## Hard rules

- Read all relevant context and source material for the task. Naming or listing a file does not count as reading it. Saying a folder contains relevant material does not count as reading that material. Reading a brief or manifest does not count as reading the files it points to.
- Do not infer a file's contents from its filename or from another document's description of it.
- If a relevant file cannot be opened, identify the missing file and stop before making any claim that depends on it.
- Follow the source trail. When an opened file points at another call, prompt, code path, framework, or record that could change the work, open that too. Continue until no unread pointer could reasonably change the understanding. Do not follow irrelevant trails to look thorough.
- If the task changes materially while the work is underway, update the Context Record and read the newly relevant material before continuing.
- A finding is something the AI comes across in the sources or the work: a conflict, something that looks wrong, something that does not add up. Findings are not facts and they are not decisions. Every finding gets discussed and confirmed with the user before anything is done about it, and fixing happens after confirming, as its own step.
- Do not treat a working label as a settled name. A term someone used in passing is not decided language. Keep a lexicon at the repo root recording how strong each term currently is, and start one the first time a naming call lands; `03 - Example/System Lexicon (DRAPER).md` shows the shape.

## The Context Record

Every substantive run assembles a Context Record before producing anything: the task as understood, every file opened, why each matters, what is current, what is historical, what was decided, what is still open, the conflicts found and their kinds, and anything discovered that belongs in another document. It is a working artifact, not a permanent one, unless the task says otherwise.

## Reporting

Report unresolved naming issues, missing Functions, unclear level boundaries, source conflicts, unavailable files, and any other consequence the work exposes. Write plainly, in full sentences that carry their own reasoning; compression that drops the reasoning is worse than length. Answer the question that was asked. Do not invent framework names, do not dramatize, and do not overstate.
